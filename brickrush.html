Featured Project

BrickRush

Built a complete browser-based arcade game for Codyza, an online volunteer coding community, with responsive controls, satisfying progression, functional power-ups, and real saved player progress without requiring a backend.

Play Game GitHub Repo

Overview

Goal

Build a complete browser-based arcade game with responsive controls, satisfying progression, functional power-ups, and real saved player progress without requiring a backend.

Gameplay

Players move a paddle to keep the ball in play and destroy every brick on the board. Clearing a layout advances the player to the next level. The first ten levels use authored layouts, then the game continues with generated levels indefinitely.

Tech Stack

  • JavaScript
  • HTML5 Canvas API
  • HTML5
  • CSS3
  • Local Storage

My Role

I designed and built the full game independently, including the game loop, Canvas rendering, collision handling, level logic, input controls, power-ups, menus, and browser-based progress storage.

Key Features

Core Gameplay

  • Ball, wall, paddle, and brick collisions
  • Score and multiple lives
  • Pause, resume, restart, and game-over states
  • Level-complete screen and next-level flow

Levels and Progression

  • Ten authored starting levels
  • Endless generated layouts after level ten
  • Increasing difficulty over time
  • Saved high score and highest level

Power-Ups

  • Wide paddle for 10 seconds
  • Multi-ball adds two balls
  • Extra life adds one life
  • Slow ball reduces speed for 8 seconds

Responsive Controls

  • Arrow keys and A/D controls
  • Mouse movement support
  • Touch and drag controls for mobile
  • Pause when the browser loses focus

Technical Highlights

  • Built a game loop with requestAnimationFrame() for smooth Canvas rendering.
  • Used delta time to keep movement and ball speed consistent across different refresh rates.
  • Implemented collision detection for the ball, paddle, walls, and individual bricks.
  • Tracked multiple active balls and only removed a life after every ball was lost.
  • Created timed power-up effects for the wide-paddle and slow-ball upgrades.
  • Built authored levels followed by procedurally generated layouts for endless progression.
  • Used localStorage to save the player’s actual high score and highest unlocked level.
  • Added keyboard, mouse, and touch controls for desktop and mobile play.

Challenges & Solutions

Challenge

A fixed amount of movement per frame causes games to run faster on high-refresh-rate monitors and slower on lower-refresh-rate screens.

Solution

I used delta time in the animation loop. Object movement is based on real elapsed time instead of a fixed number of pixels per frame, keeping gameplay consistent across devices.

Challenge

Multi-ball creates multiple active balls, so losing one ball should not immediately remove a life from the player.

Solution

I tracked every active ball separately and only removed a life when the active-ball list was empty. This made multi-ball feel useful while preserving consistent game rules.

What I Learned

  • How to structure a real-time browser game around update and render cycles.
  • How delta time prevents gameplay speed from depending on frame rate.
  • How to build and debug collision systems and interactive game states.
  • How to manage timers, temporary effects, multiple game objects, and level transitions.
  • How to support desktop and mobile input in an interactive web application.
  • How to persist real browser-based game progress using localStorage.
